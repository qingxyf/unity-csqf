# 卡牌肉鸽内容

`Assets/Scenes/forth.unity` 是独立单局流程：营地 → 随机地图节点 → 领袖战 → 本场景内结算。生命归零结束本轮；新开一局清除强化卡、藏品、事件抽牌堆和角色状态。WebGL 结算只显示新开一局；Windows 保留返回主菜单。

## 内容池

- 61 张卡牌，每张有独立绑定的 Resources 预制体、明确的 effectId 和元素插图。新增晨辉壁垒、焚烬突袭、荆棘复苏、霜潮回环、幽影收割、远行补给。
- 18 个事件。优先加载 `Resources/Events`，缺失时由 `EventPool.GetOrCreateRuntimeFallback()` 提供同轮共享的事件对象。所有合格事件抽完前不重复；源列表重排不重置抽牌堆。
- 15 件藏品。优先加载 `Resources/Collectibles`，保留代码兜底目录；随机抽取排除已拥有的 ID，重复添加不会叠加效果。集齐后，精英额外奖励 25 金币；事件和商店会显示池已耗尽。
- 3 种原创战斗小人，分别绑定普通、精英与领袖节点。美术与动画说明见 [enemy-art.md](enemy-art.md)。

## 节点行为

| 节点 | 行为 |
| --- | --- |
| 营地 | 选择休息、补给或精简卡组 |
| 普通战斗 | 2 个敌人；战后展示 3 张候选牌，至多选 2 张 |
| 精英战斗 | 更高生命和攻击；展示 4 张候选牌，至多选 2 张，额外获得未拥有藏品 |
| 领袖战斗 | 单个卡牌敌人；胜利直接完成本轮，显示本场景结算 |
| 宝藏 | 选择卡牌奖励，可跳过 |
| 商店 | 使用金币购买卡牌、藏品、恢复、刷新或移除卡牌 |
| 事件 | 选择交换生命、金币、护盾、强化卡牌、定向卡牌或藏品等奖励 |

## 战斗规则

初始 6 能量，上限 10，每个后续回合回复 2 能量。开战抽 5 张，后续回合抽 2 张，回合结束保留手牌，上限 10。牌堆抽空后重新洗入弃牌堆。1 能量基础攻击造成角色攻击力的物理伤害并结束回合。

敌人上方显示名字、生命、护盾和当前攻击意图；冻结、眩晕、束缚、沉默时显示无法行动。死亡对象立即退出战斗列表，原地播放短暂退场动画。

强化使用运行时卡牌克隆，保留原始 Resources 数据。预制体中的名称、描述、费用、CardData 引用与卡牌源数据一致；实际手牌会根据角色和藏品计算动态预览。

战斗手牌使用统一的元素边框、插图区与文本区，保留各卡牌预制体的数据绑定。扇形布局按 Canvas 边界计算位置，十张手牌也保留完整点击区域；悬停时放大并上移，以查看费用和效果。事件、奖励与商店的运行时界面使用同一参考分辨率，选择按钮保留明确高度。

新开一局会先激活地图容器再生成节点，使未序列化的图标引用在初始化前绑定；旧节点立即停用并销毁，场景背景和装饰保留。

地图以当前层为中心展示前后路线，保留两层前瞻。只移动节点显示坐标，逻辑层数和战斗镜头保持稳定，因此第十层和领袖入口仍可点击。

地图左上角提供背包和规则入口。背包使用可滚动列表展示卡名、中文元素、费用与效果，规则按完整文本高度滚动；打开时覆盖层阻止误点地图，点击关闭后恢复路线选择。

## 扩展与验证

新增卡牌时同时添加 CardData、效果目录入口及预览文案，然后运行 `python tools/generate-card-prefabs.py` 更新对应元素的预制体。生成器保留 GUID，避免破坏已绑定场景。新增事件或藏品必须使用同名 ScriptableObject 脚本的 GUID 和合法的 32 位资源 GUID。

静态 `scripts/harness/check-content.ps1` 检查资源头、MonoScript、卡牌预制体与敌人双姿态绑定。Unity EditMode 测试进一步检查真实 Resources/AssetDatabase 导入、效果组合、池的唯一性、重置及手牌边界。PlayMode 测试覆盖事件选择后继续、宝藏领取、商店购买和离开、隐藏地图重建，以及最后一击与领袖退场时序。无本地 Unity 时，使用 [CI/CD 流程](../guides/ci-cd.md) 在云端执行。
