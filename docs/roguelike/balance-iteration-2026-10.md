# 肉鸽战斗与内容完善（2026-10）

基线：`b2b5104`（最新主线）；保留逐回合能量增长、米饭事件专属藏品及原有正面战斗布局。

## 目标与边界

把难度、行动节奏与奖励从战斗控制器拆出为可调配置，让前期能够建立构筑，中后期逐渐增加压力。补齐两件米饭藏品图标，接入已修正双手的大肥鱼攻击素材。

不改变事件每轮只遇到一次、吃光米饭才解锁讨债人、事件战斗数值与专属奖励、现有卡牌效果及费用。WebGL 仍只构建 forth，Windows 仍保留全部场景；不修改 CI 条件或发布站点。

## 当前问题

- 普通战固定两人，共 155 生命 / 每回合 22 攻击；精英固定三人，共 420 生命 / 每回合 63 攻击，不随层数变化。精英可在第一层出现。
- 敌人每回合只有攻击，数值成长缺乏可以利用的防守窗口。
- 最终层仅中间一个营地，部分路径无法进入；“领袖前休息”没有被路线结构保证。
- 米饭事件的两件专属藏品缺少独立图标。

## 架构与数据路径

`MapGenerator → Node(depth) → NodeContentManager → CombatController`

- `EncounterBalance` ScriptableObject：普通、精英、领袖三个配置；人数、前后期生命/攻击/护盾/金币、行动模式。资源缺失时有相同默认值，场景和代码兜底走同一条计算路径。
- `CombatController`：取得当前层占整张地图的进度，生成敌人、结算回合与奖励；不再持有普通遭遇的具体数值公式。
- `Enemy`：保存本次遭遇的运行时行动索引，提供同源的意图预览与执行。防守不会造成伤害，重击受虚弱/烧伤影响，控制取消本次行动并推进到下一意图，死亡不再行动。
- `EventCombatEncounter`：保持优先级最高；大肥鱼维持事件自己的生命、攻击、初始盾与奖励，不接受地图曲线覆盖。
- 藏品源资源与代码兜底都引用项目中的 Sprite，不依赖临时文件。

## 验收

- EditMode：资源与兜底一致；曲线边界、单调性与固定事件优先级；意图数值和执行一致；控制/死亡不额外攻击；地图前期无精英、末层营地可达；图标真实导入。
